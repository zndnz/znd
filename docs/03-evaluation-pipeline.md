# 3. 評価パイプライン

時刻 t のフレームは「プロパティ評価 → レイヤー描画 → 合成 → 出力変換」の順で作る。
実装: `znd-core/src/{property,eval}.rs`、`znd-render/src/{compositor,raster,blend,output}.rs`。

## 3.1 プロパティ評価 `Property::eval(t)`

1. キーが無ければ `value`。最初のキー以前・最後のキー以降はそのキーの値。
2. `t` を含む区間 (k0, k1) を二分探索で求める。
3. `k0.interp_out == Hold` なら `k0.value`。
4. 両側リニアなら線形補間。
5. それ以外は、区間を (時刻, 値) 平面上の 3 次ベジェとして解く:
   - P0 = (0, v0)、P3 = (Δt, v1)
   - P1 = (影響度out·Δt, v0 + 速度out·影響度out·Δt)
   - P2 = (Δt − 影響度in·Δt, v1 − 速度in·影響度in·Δt)
   - x(s) = τ を二分法で解き（影響度 0..1 なら単調）、y(s) を返す。多次元は次元ごと。
6. 空間プロパティ（位置）は、モーションパス（空間ベジェ）の**弧長**に対して 1 次元のイージングを掛け、
   その弧長の位置を返す。リニアなら等速でパス上を進む。
7. 自動ベジェは速度＝前後のキーを結ぶ傾き、影響度 1/6。端のキーは隣接区間の傾き。
   空間の自動接線は (次のキー − 前のキー)/6。

仮定:
- ベジェとリニアが混在する区間では、リニア側を「区間の平均速度・影響度 1/3」のハンドルとして扱う。
- エクスプレッションは手順 1〜7 の後に入る（キーフレーム値を `value` として受け取り、結果で上書き）。
  レンダラーは `Resolver` トレイト越しに呼ぶだけで、評価器（QuickJS）は `znd-script` にある。
  依存先（他レイヤー・他プロパティ）は依存グラフに登録され、循環はエラーとして行番号付きで報告する。

## 3.2 トランスフォーム

レイヤー座標 → 親座標: `T(位置) · R(回転) · S(スケール/100) · T(−アンカー)`

親チェーンをたどってコンポ座標へ。不透明度は継承しない。循環があってもレイヤー数で打ち切る。

## 3.3 レイヤー描画（タイル化）

各レイヤーを、出力画素空間の矩形「タイル」（リニア・プリマルチプライド RGBA f32）にする。
`base` はコンポ座標 → 出力画素座標（プレビュー解像度 1/n のスケールを含む）。

| 種別 | ソース | 行列 |
|---|---|---|
| 平面 | 単色矩形（解析的） | `base · world` |
| フッテージ | `FootageSource::frame(item, t − start_time)` | `base · world · fit`（供給画像が公称サイズと違う場合の補正） |
| プリコンポ | ネストしたコンポを同じ手順で描いた画像 | `base · world · fit` |
| プリコンポ（コラップス） | ネストしたコンポのレイヤーを `base · world` で**直接**出力空間へ描く | — |
| ヌル・調整 | ヌルは描画なし。調整レイヤーは「ここまでの合成結果」に自分のエフェクトを掛ける（マスク・不透明度が効く範囲） | — |

ラスタライズ:
- 逆行列で出力画素中心をソース座標へ写す。
- **縁**: 出力画素のフットプリントとソース矩形の重なり面積を解析的に求めて被覆率にする。
  サブピクセル移動・回転・縮小で面積が保存される（テストで検証）。
- **色**: バイリニア（端はクランプ）。縮小時は最大 4×4 のスーパーサンプリング。
  1/4 を超える縮小ではエイリアシングが残る（ミップマップは未実装）。
- 行ごとに、ソース矩形と交わる列範囲だけを処理する。

ネストしたコンポは、そのコンポ自身のフレームグリッドに時刻を丸めて評価する（60fps コンポ内の 24fps プリコンポは 24fps で動く）。

コラップスの仮定: 中のレイヤーはプリコンポ境界で切り取られず、再サンプリングも 1 回になる。
ただし中のレイヤーの描画モードは親コンポの下の絵には届かない（透明な中間バッファ上で合成してから親に合成）。
描画モードの貫通は未対応。

## 3.4 合成

コンポのレイヤーを下から上へ:

1. 対象外を除く: 非表示、ソロが 1 つでもあれば非ソロ、ガイド（書き出し時）、イン・アウト点の外、不透明度 0。
2. タイル化（3.3）。
3. トラックマットがあれば、参照レイヤーをタイル化し（そのレイヤーの表示スイッチとは無関係）、
   アルファまたは輝度（プリマルチプライド値の Rec.709 輝度＝黒背景に置いた明るさ）を掛ける。反転は 1 − f。
4. 描画モードでキャンバスに合成。一般式（S, D はプリマルチプライド、Cs, Cb は非プリマルチプライド）:

   `out = (1 − αb)·S + (1 − αs)·D + αs·αb·B(Cb, Cs)`、`αo = αs + αb − αs·αb`

   通常・加算・乗算・スクリーンは除算のない閉じた式で処理する。ステンシル／シルエットは下の絵全体に係数を掛ける。
   HDR 値（1 超）で破綻する混合関数は入力を 0..1 に収めてから計算する。
5. `linear_blending == false` のときは、両者を表示ガンマに変換してから 4 を行い、リニアへ戻す。

最上位コンポのみ、最後に背景色を下に敷く（アルファ出力時とネスト時は敷かない）。

## 3.4.1 レイヤー 1 枚の処理順（M2 以降）

1. ソース（平面・フッテージ・プリコンポ・シェイプ・テキスト・3D モデル）。時刻はタイムリマップ／速度／コマ打ちを通した後のもの。
2. マスク（モード・フェザー・拡張）。
3. エフェクト（上から順。すべて CPU 実装）。
4. トランスフォーム。シェイプとテキストはここでベクターのまま出力空間へ直接ラスタライズする（拡大しても滲まない）。
5. モーションブラー: シャッター開区間内の複数時刻で 1〜4 を評価して平均する。フレーム全体ではなくレイヤー単位で、
   動いていないレイヤーは 1 回で済ませる。2D のみ（3D レイヤーには未対応）。
6. トラックマット → 描画モードで下の絵へ合成。

3D レイヤーが連続している区間は 1 つの「3D シーン」としてまとめ、カメラ・ライト・深度を使って描いてから 2D の合成へ戻す。

## 3.5 出力変換

- 表示・8bit 書き出し: sRGB OETF → ±0.5LSB の一様ノイズ（画素位置とフレーム番号のハッシュ、決定的）→ 量子化。
  8bit でちょうど表せる値は変化しない（純黒は純黒のまま）。
- H.264: 上記 RGB を FFmpeg で BT.709・リミテッドレンジの yuv420p に変換。
  仮定: 伝達特性は sRGB カーブで符号化し bt709 とタグ付けする（一般的な再生環境で意図どおりに見える、現行ツールと同じ慣行）。
  上映用途の既定は CRF 14・preset slow。
- 作業色空間と出力色空間は原色の 3×3 行列で変換する（sRGB / Rec.709 / Display P3 / ACEScg）。OpenColorIO・ACES の RRT/ODT は未実装。
- 16bit PNG・EXR（リニア）連番、ProRes、H.265 にも書き出せる。上映プレビューは白飛び・黒つぶれ・バンディングの警告を重ねる。

## 3.6 並列化とキャッシュ

- フレーム間: 書き出しと RAM プレビューは複数フレームを並列にレンダリングする（実測ではこちらが支配的に効く）。
- フレーム内: タイルのラスタライズと合成を行単位で並列化（小さいタイルはまとめる）。
- タイル用バッファはスレッドごとに再利用する。
- キャッシュキーはフレームの内容ハッシュ: そのフレームに存在するレイヤーの定義（JSON）と、時刻で変わる要素
  （キーフレーム・エクスプレッション・フッテージ・時間系エフェクト）の有無から作る。編集の影響を受けないフレームはキャッシュに残る。
  レイヤータイル単位のキャッシュは無い（フレーム単位のみ）。
- ディスクキャッシュは同じキーで、環境変数 `ZND_DISK_CACHE` にディレクトリを指定したときだけ有効。
