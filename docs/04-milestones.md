## GPU の実測

`znd bench [--layers N] --effects 3 [--full] [--scale 1] [--gpu]`（Apple M1。他のアプリが動いていて負荷の高い状態での計測で、
同じバイナリでも CPU の値が最大 2 倍ほどぶれる。下は合成の GPU 化の前後を同じ時間帯に交互に測ったもの。1 フレームずつ＝スクラブ時）:

| 条件 | CPU | GPU（エフェクトのみ・以前） | GPU（合成まで・現在） |
|---|---|---|---|
| 小さいレイヤー 200 枚 × エフェクト 3 個、1/2 解像度 | 600〜1000 ms | 1155 ms | **181 ms** |
| 小さいレイヤー 200 枚・エフェクトなし、1/2 解像度 | 43〜78 ms | 76 ms | **16 ms** |
| 画面いっぱいのレイヤー 12 枚 × エフェクト 3 個、1/2 解像度 | 400〜600 ms | 175 ms | 154 ms |
| 同上、フル解像度 | 2400〜2700 ms | 692 ms | 726 ms |

合成の GPU 化（[gpu_composite.rs](../crates/znd-render/src/gpu_composite.rs)、[composite.rs](../crates/znd-gpu/src/composite.rs)）で、
レイヤーのソース・エフェクト・配置（スーパーサンプル込み）・描画モード 31 種の重ね合わせを GPU の上で済ませ、完成したフレームだけを読み戻す。
小さいレイヤーが大量にある条件は 5 倍以上速くなった。画面いっぱいの重いエフェクトはもともと GPU で処理していたので、ほぼ変わらない。
**目標の「200 レイヤー・エフェクト多段で 1/2 解像度がリアルタイム近く」には、まだ 5 fps 前後で届いていない**（残りは GPU 上のぼかしの計算そのもの）。

- GPU に載せるのは、平面・フッテージ・プリコンポで、マスク・トラックマット・モーションブラーが無く、エフェクトがすべて GPU 対応のレイヤー。
  それ以外（シェイプ・テキスト・マスク付きなど）は CPU で出力空間のタイルまで作り、重ねる処理だけを GPU で行う。
  3D レイヤーか調整レイヤーがあるコンポは、そのコンポだけ CPU で合成する。
- GPU の処理は 1 フレームずつ（複数スレッドから来ても順番に）行う。画面いっぱいの条件では、RAM プレビューの並列レンダリングが以前より少し遅い。
- wgpu の Metal では描画パスごとにコマンドバッファが作られるため、小さい画像のエフェクトと配置はコンピュートシェーダーにして
  1 つのパスに積む（[batch.rs](../crates/znd-gpu/src/batch.rs)）。大きな画像のエフェクトは描画パスのほうが速いので従来どおり。

GPU と CPU の結果の差は最大 0.002（8bit の 1 段未満）で、対応する全エフェクトと、合成（描画モード 31 種・回転と縮小・表示ガンマ空間・8bpc・
1/2 解像度・CPU のタイルとの混在・ステンシル）を自動テストで比較している（[composite_parity.rs](../crates/znd-gpu/tests/composite_parity.rs)）。
書き出しは既定で CPU、`--gpu` で GPU。アプリのプレビューは GPU が使えれば使う（ウィンドウメニューで切り替え）。

## 次にやるべきこと（優先順）

1. 残りのエフェクト（ノイズ系・パーティクル・時間系など約 30 種）の GPU 実装。マスクとトラックマットの GPU 化（いまは CPU でタイルを作る）。
2. GPU 上のぼかしの高速化（縮小してからぼかす、分離可能なパスの統合）。リアルタイムの目標に向けて。
3. OpenFX: オーバーレイ、マスク入力、ジェネレーター。市販プラグインでの検証。
4. Photoshop / Illustrator の実ファイルでの読み込み検証。PDF のテキストとグラデーション。
5. 3D カメラトラッカー、AI セグメンテーション、オプティカルフロー、パネルのドッキング。
