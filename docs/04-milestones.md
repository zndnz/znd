# 4. マイルストーン計画と実装状況

M1〜M5 を通して実装した。ただし要件のすべてではない。**「未実装・簡易実装」の節を必ず読むこと。**
受け入れ基準と、どこまで自動テストで確認したかは [05-acceptance-criteria.md](05-acceptance-criteria.md)。

凡例: ✅ 実装しテスト済み ／ 🟡 実装したが簡易版・制約あり ／ ❌ 未実装

## GPU の実測

`znd bench --effects 3 [--full] [--gpu]`（Apple M1。他のアプリが動いていて負荷の高い状態での計測なので、絶対値は目安）:

| 条件 | CPU | GPU |
|---|---|---|
| 画面いっぱいのレイヤー 12 枚 × エフェクト 3 個、1/2 解像度 | 379 ms/フレーム | 88 ms/フレーム |
| 同上、フル解像度 | 1656 ms/フレーム | 440 ms/フレーム |
| 小さいレイヤー 200 枚 × エフェクト 3 個、1/2 解像度 | 547 ms/フレーム | 538 ms/フレーム |

画面全体に掛かる重いエフェクトは 3〜4 倍速くなったが、**目標の「1080p・200 レイヤー・エフェクト多段で 1/2 解像度がリアルタイム近く」には届いていない。**
小さいレイヤーは GPU への往復のほうが高くつくので CPU で処理している（10 万画素未満）。合成まで GPU に載せないと、ここは速くならない。

GPU と CPU の結果の差は最大 0.002（8bit の 1 段未満）で、対応する全エフェクトを自動テストで比較している。
書き出しは既定で CPU、`--gpu` で GPU。アプリのプレビューは GPU が使えれば使う（ウィンドウメニューで切り替え）。

## 次にやるべきこと（優先順）

1. **合成の GPU 化**: レイヤーのラスタライズと合成を GPU に載せ、フレームを最後まで GPU 上に置く。小さいレイヤーが多い条件はこれでしか速くならない。
2. 残りのエフェクト（ノイズ系・パーティクル・時間系など約 30 種）の GPU 実装。
3. OpenFX: オーバーレイ、マスク入力、ジェネレーター。市販プラグインでの検証。
4. Photoshop / Illustrator の実ファイルでの読み込み検証。PDF のテキストとグラデーション。
5. 3D カメラトラッカー、AI セグメンテーション、オプティカルフロー、パネルのドッキング。
